# AOP:TC4 Compact

<img src="src/main/resources/logo.png" alt="AOP:TC4 Compact" width="128" height="128">

Необязательная интеграция рецептов и подсказок для **AOP: Thaumcraft 4**, **Minecraft 1.21.1 / NeoForge**.

[English](README.md) | [Авторство](NOTICE.md)

## О проекте

AOP:TC4 Compact добавляет рецепты Thaumcraft в JEI и EMI, а сведения о блоках - в Jade и WTHIT. Поддержка устройств Thaumic Tinkerer включается при наличии аддона.

Рецепты показывают требования исследований, количество аспектов и стоимость виса. Неизвестные аспекты скрываются в соответствии с настройками. Подсказки ядра отображают эссенцию через публичные контракты контейнеров и труб. Подсказки Tinkerer включают инструмент планшета, цель трансвектора, состояние ремонта и режимы магнитов.

## Совместимость

Требуются Java **21**, NeoForge **от 21.1.252 в пределах 21.1**, совместимая сборка **AOP: Thaumcraft 4 1.0.0** и **AOP: UI 0.7.x**. Для отображения рецептов или подсказок необходима хотя бы одна поддерживаемая интеграция.

| Интеграция | Поддерживаемый диапазон | Назначение |
| --- | --- | --- |
| JEI | От 19.8.4.110 до 20, не включая 20 | Просмотр рецептов |
| EMI | От 1.1.13 до 1.2, не включая 1.2 | Просмотр рецептов |
| Jade | От 15.10 до 16, не включая 16 | Подсказки блоков |
| WTHIT | От 12.5 до 13, не включая 13 | Подсказки блоков |

Все зависимости должны быть предназначены для Minecraft 1.21.1 / NeoForge. При наличии обоих просмотрщиков рецептов используется EMI. Интеграции Jade и WTHIT работают независимо. Thaumic Tinkerer необязателен.

## Установка

Файл `aoptc4-compact-0.7.0.jar` устанавливается в каталог `mods` клиента вместе с ядром, AOP: UI и выбранными просмотрщиками, включая их зависимости.

Существующий JAR `thaumcraft-viewers` необходимо заменить; оба файла одновременно не устанавливаются. Mod ID остаётся `thaumcraft_viewers` для совместимости конфигурации.

### Выделенный сервер

Установка Compact на сервер необязательна. Вместе с Jade или WTHIT мод предоставляет достоверные серверные данные блоков. Без серверной установки подсказки используют синхронизированное состояние, доступное клиенту; несинхронизированные инвентари могут быть недоступны.

AOP: UI требуется везде, где установлен Compact, и независимо требуется ядром. JEI и EMI не нужны на выделенном сервере. Tinkerer остаётся необязательным с обеих сторон.

## Настройка

Настройки хранятся в `thaumcraft_viewers-client.toml` и доступны в AOP: UI через Mods, шестерёнку Таумономикона или меню паузы. Клиентские изменения сохраняются сразу.

| Параметр | По умолчанию | Альтернативное значение |
| --- | --- | --- |
| `recipes` | `ALL_WITH_REQUIREMENTS` | `RESEARCHED_ONLY` |
| `aspects` | `SCANNED_ONLY` | `ALL` |

Исходные ключи конфигурации и значения по умолчанию сохранены. Настройки отображения не отменяют серверные проверки исследований и создания предметов.

## Сборка из исходников

PowerShell-обёртка поддерживает локальную рабочую папку: при наличии `.aop-workspace` в родительском каталоге сборки, кэши и профили запусков остаются там. Без этого маркера используются обычные каталоги `build/` и `runs/` репозитория. Явный путь вывода задаётся через `-PaopWorkspace=<каталог>`.

Требуются JDK 21 и совместимые артефакты AOP: UI, API Thaumcraft и Tinkerer:

```powershell
$dependencies = @(
    '-PaopUiJar=C:/dependencies/aopui-1.21.1-0.7.0.jar'
    '-PthaumcraftApiJar=C:/dependencies/thaumcraft-api-1.0.0.jar'
    '-PtinkererJar=C:/dependencies/ThaumicTinkerer-1.21.1-1.0.0.jar'
)
./gradlew.ps1 build @dependencies
```

В Linux и macOS используется `sh ./gradlew` с теми же параметрами Gradle. Зависимости также можно разместить в `libs/` с именами из `build.gradle`. Tinkerer требуется при компиляции необязательного адаптера, но не при запуске. Классы зависимостей в результат не включаются.

Игровой артефакт: `build/libs/aoptc4-compact-0.7.0.jar`.

## Проверки

`build` выполняет проверки представления рецептов и изолированной совместимости JEI/EMI, а также компилирует нативные проверки подсказок. Профили просмотрщиков выбираются через `check -PviewerCompatibility=minimum`, `middle` или `latest`.

Нативные GameTest требуют игрового ядра через `thaumcraftRuntimeJar` и параметров соответствующих необязательных интеграций. Автоматические проверки не подтверждают визуальную совместимость всех сочетаний клиента и сервера.

Сообщение об ошибке должно содержать версии ядра, Compact и просмотрщиков, шаги воспроизведения и соответствующий журнал.

## Непрерывная интеграция

Для выпуска обычного GitHub Release откройте **Actions → Build and release → Run workflow** и включите **release**. Релиз получает тег `v<версия>`. Пустое поле **version** использует `mod_version` из `gradle.properties`; значение `major.minor.patch` переопределяет версию только для этого запуска. Выбранная версия применяется к метаданным JAR, именам файлов и тегу; исходные файлы workflow не изменяет. Суффиксы предварительных версий в режиме релиза отклоняются. Существующие теги релизов не перезаписываются. При выключенном **release** ручной запуск только собирает артефакты. Локальный `act` ничего не публикует. Заметки обычного релиза содержат все коммиты после ближайшего предыдущего обычного релиза в выбранной истории, ссылки на коммиты и сравнение. Первый релиз включает всю историю. В nightly этот список не добавляется.

Для локального запуска `act` подготовьте совместимые исходники зависимостей в `.dependencies/aopui`, `.dependencies/thaumcraft`, `.dependencies/tinkerer`, затем выполните `act workflow_dispatch --input release=true`. Локальная проверка использует эти каталоги и пропускает публикацию на GitHub. Для приватных зависимостей задайте необязательный секрет `DEPENDENCY_TOKEN` с правом чтения соответствующих репозиториев.

GitHub workflow запускается при изменении исходников и сборочных файлов. Правки только документации сборку не запускают.

| Переменная репозитория | Назначение / значение по умолчанию |
| --- | --- |
| `THAUMCRAFT_REPOSITORY` | Исходники ядра; `Salossov/aop-thaumcraft-4` |
| `THAUMCRAFT_REF` | Ревизия ядра; `main` |
| `TINKERER_REPOSITORY` | Исходники Tinkerer; `Salossov/aoptc4-thaumic-tinkerer` |
| `TINKERER_REF` | Ревизия Tinkerer; `main` |
| `AOPUI_REPOSITORY` | Исходники AOP: UI; `Salossov/aop-ui` |
| `AOPUI_REF` | Ревизия AOP: UI; `main` |

Для всех зависимостей выбираются совместимые ревизии. Загрузка приватных репозиториев требует токен с правом чтения.
